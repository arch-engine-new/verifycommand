## 2. 认证与签名（OPEN-BODY-SIG）

请求头：
```
Authorization: OPEN-BODY-SIG AppId="xxx", Timestamp="20260818120000", Nonce="xxxx", Signature="xxx"
```

签名算法（服务端实现，务必与银联"天满平台签名比对工具"联调验证）：
1. B = SHA256_hex(报文体原始字节)
2. C = AppId + Timestamp + Nonce + B（UTF-8 字符串拼接）
3. E = HmacSHA256(C, AppKey)
4. Signature = Base64(E)

> 参数获取：AppId/AppKey 由银联商务提供（**测试参数已有，开发/联调直接使用**）；首筑主体微信子商户参数**待正式生效后由银联商务下发**（凭据不进本文档）；物业 APP 的银联商户号按物业主体另行申请。

## 4. 下单接口（核心）—— app/pay

### 4.1 我方组装（支付中心 → 银联）

```json
{
  "mchntOrderId": "3194...（商户订单号，生成规则见下）",
  "vaMchntNo": "物业公司银联商户号",
  "vaTermNo": "终端号",
  "instMid": "APPDEFAULT",
  "msgType": "wx.unifiedOrder",          // 已确认：微信APP原生=wx.unifiedOrder；支付宝=trade.appPreOrder(新版小程序)；银行卡/云闪付=uac.appOrder(银联统一收银台)；间连支付宝=trade.precreate
  "subAppId": "物业公司微信子商户AppID",   // 微信必传
  "orderDesc": "XX小区2026-07物业费",
  "totalAmount": "10000",                // 单位分
  "notifyUrl": "https://pay.shuzhu.com/notify/chinaums",
  "attachedData": "P20260818000001",     // 我方支付单号，透传定位
  "expireTime": "2026-08-18 12:15:00",
  "srcReserve": "JSON扩展",
  "vaFld": {
    "newShopFlag": "GWCXS",
    "isSubMchntPay": "02"                // 子商户上送交易
    // 一期不传 satType/satInfo：银联规则 satInfo 为空时上送分账字段可能拒单；
    // 二期启用分账时再上送 satType=01 + satInfo（各分账方 satAmt / feeBear）
  }
}
```

**商户订单号生成规则**（银联建议）：`{来源编号4位}{yyyyMMddHHmmssSSS 17位}{7位随机数}`，合计 28 位 ≤32；**支付中心生成，作为支付单与银联订单的关联键**。

**分账预留说明（对应决策#4/#5）**：
- 一期：`isSubMchntPay=02` 上送（子商户交易），**不传 satType/satInfo**——资金全额结算给子商户；
- 二期启用分账：satInfo 上送各分账方（物业子商户 satAmt + 首筑服务费子商户 satAmt），手续费承担方用 `feeBear=Y` 标注；
- 数据模型已含 division_flag/sat_info 字段，二期无需改表。

### 4.2 响应处理（银联 → 支付中心）

| 关键字段 | 用途 |
|---|---|
| respCode / respDesc | 0000 成功；否则下单失败 |
| status | TRADE_SUCCESS 已支付（极少，兜底处理）/ WAIT_BUYER_PAY 等待支付 |
| appPayRequest | **APP 支付要素（带签名）**，用于调起微信/支付宝 |
| prepayId / targetOrderId | 渠道单号 |
| mchntOrderId | 商户订单号回显（校验一致性） |

**状态枚举（必须全量映射）**：
```
NEW_ORDER 新订单 | WAIT_BUYER_PAY 等待支付 | TRADE_SUCCESS 支付成功
TRADE_CLOSED 已关闭 | TRADE_REFUND 转入退款 | UNKNOWN 未明确
```

**appPayRequest 内层结构（SDK 文档确认，支付中心透传、C 端 SDK 解析）**：

| 支付方式 | appPayRequest 内容 | C 端调起方式 |
|---|---|---|
| 微信原生 | appid/partnerid/prepayid/noncestr/package/sign/timestamp | 银联综合支付 SDK，payChannel=CHANNEL_WEIXIN(01) |
| 支付宝（3.0.9+ 跳小程序） | appScheme/minipath/miniuser/msgType/noncestr/package/prepayid/sign/timestamp | payChannel=CHANNEL_ALIMINIPAY(03)；scheme 回调取 errCode/errStr |
| 云闪付 | tn | UPPayAssistEx.startPay(activity,null,null,tn,"00")；onActivityResult 取 pay_result=success/fail/cancel |
| 间连支付宝 | orderStr（传给支付宝 SDK） | 依赖支付宝 SDK 的 aar：payChannel=CHANNEL_ALI_SDK |

**支付结果权威性（SDK 文档原话）**：SDK 返回的 resultCode 仅表示"支付请求发送结果"，**商户订单是否成功支付必须以商户后台收到支付通知或查询 API 结果为准**——严禁以客户端 SDK 回调结果直接入账（与 01/02 的"跳回传参不可信，一律查单"一致）。

**未明确处理**：respCode 非 0000 或 status=UNKNOWN → 不落支付成功；启动查单兜底（重试 ≥3 次，间隔 5s/30s/60s）。

## 5. 支付结果查询 —— online/query

`POST /v1/inip/upsp/shop/online/query`（不使用 app/pay-query，见 §3 B1 定稿）

请求（必传）：
```json
{
  "mchntOrderId": "商户订单号",
  "vaMchntNo": "商户号",
  "vaTermNo": "终端号",
  "sysSource": "OPT",
  "vaFld": { "newShopFlag": "GWCXS" }
}
```

响应关键字段：status、payTime、targetSys（WXPay/ALIPAY/UNIONPAY）、targetOrderId、settleDate、totalAmount、**cardAttr（DEBIT_CARD/CREDIT_CARD，银行卡交易卡种，落 txn_flow 计费率）**。

**用途**：支付结果查询（C 端跳回查单、超时兜底、对账前修正）。

## 6. 退款（退货）—— online/refund

`POST /v1/inip/upsp/shop/online/refund`（不使用 app/refund）；退款查询 `POST /v1/inip/upsp/shop/online/refund-query`（请求同 §5，mchntOrderId 传**退款订单号**）

```json
{
  "mchntOrderId": "原消费商户订单号",
  "vaMchntNo": "商户号",
  "vaTermNo": "终端号",
  "refundOrderId": "退款订单号（同生成规则，唯一）",
  "refundAmount": "10000",
  "sysSource": "OPT",
  "vaFld": {
    "newShopFlag": "GWCXS",
    "isSubMchntPay": "02"
    // 一期不传 satType/satInfo（同下单，二期启用分账时上送）
  }
}
```

响应关键字段：refundStatus（SUCCESS 成功 / FAIL 失败 / PROCESSING 处理中 / **UNKNOWN 需查询**）、refundOrderId、refundAmount。

> **退款规则（银联答复确认）**：退款时限**最大 360 天**；退款**会返还手续费**；退款到账时效取决于微信/支付宝/银行实际上账时间——渠道返回"退款成功"仅表示**收到退款请求**，并非已上账；常规：微信零钱/支付宝余额基本准实时，银行卡看各银行处理时效。
> 状态枚举以 `SUCCESS` 为准（SDK 文档返回示例均为 errCode=SUCCESS）；代码按 SUCCESS 匹配，**任何未知值一律走退款查询兜底**（防文档笔误/异常返回）。

**退款兜底**：refundStatus ∉ {SUCCESS, FAIL} → 调 online/refund-query 即时补查（间隔 5s/30s/60s/5min）；仍未明确的由「退款超时扫描任务」接管（见 01 §7.3）。

## 7. 通知接收（银联 → 我方，线上交易订单通知）

- 我方提供 notifyUrl，银联 POST 通知（ContentType 空，按表单/JSON 兼容解析）
- **必验签**：报文含 sign/signType，验签失败丢弃并告警（防伪造）。密钥为下单 `sysSource`（同网付 msgSrc）在新购物车录入的通讯密钥；算法按网付规则：除 sign 外参数按 key 字典序拼 `k=v&…`，末尾拼密钥，按 signType（SHA256，缺省 MD5）取摘要转大写十六进制比对。**PDF 未写明，空值是否参与、报文格式须用测试通知实测确认**（见 23 文档 C1）
- **来源 IP 加白**：通知接收端仅放行银商出口 IP（APP 支付 PDF 生产 Q4 列表）
- **幂等**：以 mchntOrderId + notifyId 去重；重复通知不重复入账
- **响应**：处理成功返回 `SUCCESS`，失败返回 `FAILED`（银联将重发）

通知关键字段：**mid/tid（必填，通知参数以 mid/tid 为主，兼容 vaMchntNo/vaTermNo）**、mchntOrderId、status（订单状态）、totalAmount、payTime、targetSys、seqId、cardAttr、refundAmount / refundOrderId（退款通知时）、notifyId、sign、signType。

> 通知**无 refundStatus 字段**：退款通知以 `status=TRADE_REFUND` + `refundOrderId` 匹配退款单，退款成败最终以 online/refund-query 的 refundStatus 为准。

## 11. App 支付 SDK 集成要点（V3.1.8，银联已提供）

**来源**：`全民付APP支付sdkV3.1.8/`（Android aar / iOS a / 鸿蒙 har 三套 + 技术文档 V1.1.7，2025-02-12 更新）。

### Android
- 集成：aar + libs 目录所有 so/jar；Gradle 加微信依赖 `com.tencent.mm.opensdk:wechat-sdk-android-without-mta:5.5.8`、支付宝 `com.alipay.sdk:alipaysdk-android`
- AndroidManifest 声明：`<meta-data android:name="PPPaySDK" android:value="true"/>`、`CurrentEnvironment=PROD`；云闪付需 `uses-library org.simalliance.openmobileapi` + UPPayWapActivity + NFC 权限
- **安卓 11 包名可见性**：`<queries>` 声明 com.unionpay / com.tencent.mm / com.eg.android.AlipayGphone，否则"支付客户端未安装"误报

- 结果：`setPayListener.onResult(resultCode, resultInfo)`；云闪付走 `onActivityResult`（pay_result=success/fail/cancel）
- 微信回调：WXEntryActivity.onResp（放包名 wxapi 目录，exported=true、singleTask）

**SDK 结果码（表 12，注意：仅表示支付请求发送结果，非支付结果）**：

| resultCode | 含义 | 我方处理 |
|---|---|---|
| 0000 | 支付请求发送成功 | **仍需查单/通知确认** |
| 1000 | 用户取消支付 | 支付单保持 WAIT_PAY，可重试 |
| 1001 | 参数错误（appid 未配置/三者不一致） | 记日志+告警（配置问题） |

| 1003 | 支付客户端未安装 | 提示用户安装（安卓 11 需检查 queries 声明） |
| 2001 | 订单处理中，结果未知 | 查单兜底 |
| 2002 | 订单号重复 | 幂等处理 |
| 2003 | 订单支付失败 | 支付单保持 WAIT_PAY，可重试 |
| 9999 | 其他支付错误 | 提示稍后重试 |
