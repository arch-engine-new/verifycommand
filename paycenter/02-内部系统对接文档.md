## 1. 对接总览

### 1.1 对接方
- **首筑物业 C 端 APP**（业主侧）：支付方式选择（原生）、创建支付单、**用银联 SDK 调起支付**、查单、接收回调（退款申请二期）
- **B 端物业系统**（物业侧）：接收支付/退款回调，回写账单；交易查询（收款查看）

### 1.2 基础约定
- 协议：HTTPS
- 内容类型：application/json; charset=utf-8
- 字符集：UTF-8
- 金额单位：**分（整数）**
- 时间格式：yyyy-MM-dd HH:mm:ss
- 幂等键：`biz_order_no`（创建支付单）/ `biz_refund_no`（创建退款单），**重复请求返回原单，不重复创建**
- 鉴权：`Authorization: Bearer <access_token>`；access_token 由"获取访问令牌"接口下发，有效期 2 小时，中控服务管理刷新

### 1.3 通用返回结构

```json
{
  "code": "0000",
  "message": "成功",
  "data": { }
}
```

| code | 说明 |
|---|---|
| 0000 | 成功 |
| 1001 | 参数错误 |
| 1002 | 鉴权失败（签名/密钥错误） |
| 1003 | token 过期或无效（重新获取令牌） |
| 2001 | 商户未配置或已停用 |
| 2002 | 支付方式未开通（开关关闭） |
| 2003 | 业务单号已存在（幂等返回原单，data 含原单信息） |
| 2004 | 账单存在进行中的支付单（同 biz_bill_no 已有 WAIT_PAY/PAID/REFUNDING 单） |
| 2005 | 金额超限（超过商户/通道单笔限额） |
| 3001 | 支付单不存在 |
| 3002 | 支付单状态不允许该操作（如已支付单重复下单） |
| 3003 | 退款金额超限 / 不可退 |
| 3004 | 原支付单状态不允许退款（非 PAID） |
| 4001 | 协议未确认（用户未同意当前版本《支付服务说明》，需弹窗确认后重试） |
| 5001 | 通道异常（可重试） |
| 9999 | 系统繁忙 |

**错误码三层映射（银联 → 支付中心 → 用户文案，防"错误码裸奔"）**：

| 银联侧（raw/联调核实） | 支付中心 | 用户可见文案 | 处理 |
|---|---|---|---|
| respCode=0000 | 0000 | — | 正常 |
| errCode=1001 授权失败（appId 无对应交易权限） | 5001 | "该支付方式暂不可用，请稍后重试" | 记日志+告警，不重试（配置问题） |
| errCode=1000 认证失败（签名/密钥/token 失效） | 9999 | "系统繁忙，请稍后重试" | 记日志+告警（内部配置问题） |
| errCode=9200 系统繁忙（限流） | 5001 | "支付通道繁忙，请稍后重试" | 退避重试 ≤3 次 |
| 其他非 0000 / 未知 | 5001 | "支付未完成，请稍后在缴费记录中确认" | 走查询兜底（FR-15） |
| status=UNKNOWN | WAIT_PAY+查单 | "支付结果确认中…" | 查询兜底，严禁直接判失败 |

## 3. 接口定义

### 3.1 获取访问令牌

`POST /v1/token`

请求：
```json
{
  "app_id": "业务系统应用标识（由支付中心分配）",
  "app_secret": "业务系统密钥",
  "timestamp": "20260818120000"
}
```
> `timestamp` 格式：**yyyyMMddHHmmss**（本接口与其他接口的 yyyy-MM-dd HH:mm:ss 不同，按字段标注为准）
响应 data：
```json
{
  "access_token": "xxx",
  "expires_in": 7200
}
```

### 3.2 创建支付单

`POST /v1/pay/orders`

**无收银台模式下 C 端先选支付方式再下单**：① 调 3.9 商户支付方式查询 → ② 原生页面展示可用方式 → ③ 用户选定后携 `pay_method` 调本接口。

请求：
```json
{
  "merchant_code": "WY001",
  "biz_order_no": "BIZ20260818001",
  "biz_user_id": "业主用户ID",
  "total_amount": 10000,
  "pay_method": "WECHAT",
  "expire_minutes": 15,
  "subject": "XX小区物业费",
  "notify_url": "https://biz.example.com/pay/callback",
  "return_url": "szwuyapp://payresult",
  "items": [
    {
      "biz_bill_no": "BILL20260701001",
      "bill_type": "PROPERTY_FEE",
      "amount": 7000,
      "billed_period": "2026-07"
    }
  ],
  "reserve": "扩展字段(JSON字符串,原样透传)"
}
```

**请求字段清单（开发必读）**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| merchant_code | string(32) | 是 | 物业公司商户编码（支付中心配置） |
| biz_order_no | string(64) | 是 | 业务系统幂等单号，唯一 |
| biz_user_id | string(64) | 是 | 业主标识 |
| total_amount | long | 是 | 支付金额（分），>0 且 ≤ 商户单笔限额（默认 5000000 分=5 万，商户配置可调） |
| pay_method | string(20) | **是** | 支付方式枚举（见 §4；**必须为 3.9 查询结果中 enabled=true 的一项**） |
| expire_minutes | int | 否 | 支付超时（默认15，范围 5-60） |
| subject | string(128) | 否 | 订单标题（≤128，微信限制128字节） |
| notify_url | string(256) | 是 | 支付结果回调地址；**域名必须在商户配置的 notify_domain 白名单内**，否则拒绝（防篡改回调地址） |
| return_url | string(256) | 是 | 支付完成回跳 APP scheme（银联 App 支付跳回用） |
| items | array | 是 | 账单明细。**一期服务端限制恰好 1 条**（超出返回 1001 参数错误）；结构保留数组，二期放开为 ≤50 条多账单合并 |
| items.biz_bill_no | string(64) | 是 | 业务账单号 |
| items.bill_type | string(32) | 是 | PROPERTY_FEE / PARKING_MONTHLY（扩展枚举） |
| items.amount | long | 是 | 单账单金额（分），**合计必须=total_amount** |
| items.billed_period | string(16) | 否 | 账期（如 2026-07） |
| reserve | string(512) | 否 | 透传字段（JSON 字符串，回调原样带回） |

**服务端校验（创建时按序执行）**：
1. 幂等：同 `biz_order_no` 已存在 → 返回原单（code=2003）
2. 账单在途锁定：items 中任一 `biz_bill_no` 已存在 **WAIT_PAY / PAID / REFUNDING** 状态的支付单 → 拒绝（code=2004，防并发/重复缴费）
3. 金额：`total_amount` > 0 且 ≤ 商户单笔限额（code=2005）
4. 支付方式：`pay_method` 必填且该校验商户开关（code=2002）
5. 协议校验：该用户 PAY_SERVICE 当前版本未同意 → 4001（C 端弹窗引导确认后重试）
6. notify_url 域名 ∈ 商户白名单（否则 1001）
7. 校验通过 → 调银联 app/pay 下单（**同步返回**），失败透传通道错误（5001）

响应 data：
```json
{
  "pay_order_id": "P20260818000001",
  "status": "WAIT_PAY",
  "pay_params": {
    "target_sys": "WECHAT",
    "app_pay_request": "银联返回的APP支付要素(带签名,原样透传)",
    "target_order_id": "渠道单号",
    "mchnt_order_id": "银联商户订单号"
  },
  "expire_time": "2026-08-18 12:15:00"
}
```

**响应字段清单（开发必读）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| pay_order_id | string(32) | 支付中心支付单号 |
| status | string(20) | WAIT_PAY（本接口只返回待支付态） |
| pay_params.target_sys | string(20) | 渠道标识：WECHAT / ALIPAY / UNIONPAY / UAC（C 端据此选择对应 SDK/收银台） |
| pay_params.app_pay_request | string | **银联 APP 支付要素（带签名）**：原样传给银联 SDK 的调起参数，**禁止修改**；内层结构按渠道区分（微信 prepayid/支付宝 minipath/云闪付 tn/间连支付宝 orderStr，详见 04 §4.2） |
| pay_params.target_order_id | string | 渠道单号（日志/排查用） |
| pay_params.mchnt_order_id | string | 银联商户订单号（与下单时一致，可校验） |
| expire_time | datetime | 支付过期时间（到期后 C 端不可再调起） |

**C 端动作**：将 `pay_params` 传入银联 App 支付 SDK 直接调起微信/支付宝/银联收银页；业主完成支付后回跳 `return_url`。**不再有任何 WebView/收银台页面**。

### 3.3 支付单查询

`POST /v1/pay/orders/query`

请求：
```json
{ "pay_order_id": "P20260818000001", "biz_order_no": "BIZ20260818001" }
```
（二者至少传一）

响应 data：
```json
{
  "pay_order_id": "P20260818000001",
  "status": "PAID",
  "total_amount": 10000,
  "pay_method": "WECHAT",
  "channel_order_id": "银联商户订单号",
  "channel_txn_id": "银联流水号",
  "pay_time": "2026-08-18 12:01:03",
  "items": [ { "biz_bill_no": "BILL20260701001", "bill_type": "PROPERTY_FEE", "amount": 7000 } ]
}
```
> `pay_method` 为下单时提交的支付方式；未成交时也返回。银行卡交易成交后另返回 `card_attr`（DEBIT_CARD / CREDIT_CARD），未成交或非银行卡为 null。

### 3.4 创建退款单

`POST /v1/refund/orders`

请求：
```json
{
  "merchant_code": "WY001",
  "pay_order_id": "P20260818000001",
  "biz_refund_no": "R20260818001",
  "refund_amount": 10000,
  "reason": "重复缴费",
  "reviewer": "物业操作员",
  "notify_url": "https://biz.example.com/refund/callback"
}
```

| 约束 | 说明 |
|---|---|
| 一期仅支持全额退款 | refund_amount 必须=原单 total_amount |
| 原支付单状态 | **必须为 PAID**（REFUNDING/REFUNDED/CLOSED/WAIT_PAY 均拒绝，code=3004） |
| 已退款单不可重复退 | 幂等按 biz_refund_no |
| 退款时效 | 原支付成功之日起 ≤ **360 天**（银联答复确认，原"12 个月"说法已修正） |
| 到账时效 | 原路退回：零钱/余额**即时**；银行卡 **0-3 个工作日**（C 端/B 端展示时引用此说明） |
| 手续费返还 | 已结算退款：银联按比例返还已收手续费（refund_fee_return 记录，二期对账核对）；未结算退款：轧差计算 |
| 退款失败 | 原支付单状态回 PAID（可重新发起）；商户资金不足（已结算场景）→ REFUND_FAIL 并分类提示 |

响应 data：
```json
{
  "refund_order_id": "R20260818000001",
  "status": "REFUNDING"
}
```

### 3.5 退款单查询

`POST /v1/refund/orders/query`

请求：`{ "refund_order_id": "R20260818000001", "biz_refund_no": "R20260818001" }`

响应 data：
```json
{
  "refund_order_id": "R20260818000001",
  "status": "REFUND_SUCCESS",
  "refund_amount": 10000,
  "channel_refund_id": "银联退货单号",
  "refund_time": "2026-08-18 13:00:00"
}
```

### 3.6 支付结果回调（支付中心 → 业务系统）

- 触发时机：支付单状态收敛为 PAID / CLOSED（或长时间 UNKNOWN 的最终兜底结果）
- 重试：指数退避（1m/2m/4m/8m/16m，共 5 次），业务系统返回 HTTP 200 且 body `{"code":"0000"}` 视为成功
- 安全：回调带三个头 `X-Timestamp`（yyyyMMddHHmmss）、`X-Nonce`（32 位随机串）、`X-Sign`
  - `X-Sign = Base64(HmacSHA256(key=app_secret, data=X-Timestamp + "\n" + X-Nonce + "\n" + 原始报文体UTF-8))`
  - 接收方校验：签名一致且 X-Timestamp 与本地时间差 ≤ 5 分钟，X-Nonce 5 分钟内不重复；否则丢弃并告警
  - 3.7 退款结果回调同此规则

报文：
```json
{
  "event": "PAY_SUCCESS",
  "pay_order_id": "P20260818000001",
  "biz_order_no": "BIZ20260818001",
  "merchant_code": "WY001",
  "total_amount": 10000,
  "pay_method": "WECHAT",
  "pay_time": "2026-08-18 12:01:03",
  "channel_order_id": "银联商户订单号",
  "items": [ { "biz_bill_no": "BILL20260701001", "bill_type": "PROPERTY_FEE", "amount": 7000 } ]
}
```

| event | 含义 |
|---|---|
| PAY_SUCCESS | 支付成功（B 端据此回写账单已缴） |
| PAY_CLOSED | 订单关闭 |

### 3.7 退款结果回调

```json
{
  "event": "REFUND_SUCCESS",
  "refund_order_id": "R20260818000001",
  "biz_refund_no": "R20260818001",
  "pay_order_id": "P20260818000001",
  "refund_amount": 10000,
  "refund_time": "2026-08-18 13:00:00"
}
```

| event | 含义 |
|---|---|
| REFUND_SUCCESS | 退款成功（B 端据此更新账单为已退） |
| REFUND_FAIL | 退款失败（可重新发起） |

### 3.8 关闭支付单

`POST /v1/pay/orders/close`

请求：
```json
{ "pay_order_id": "P20260818000001", "close_reason": "USER_CANCEL" }
```

| 约束 | 说明 |
|---|---|
| 仅 WAIT_PAY 可关闭 | PAID/REFUNDING/CLOSED 拒绝（code=3002） |
| 关闭动作 | 调银联 order-close（尽力而为，银联失败不影响本地置 CLOSED） |
| 使用方 | C 端 APP"取消支付"、支付中心超时任务 |

响应 data：
```json
{ "pay_order_id": "P20260818000001", "status": "CLOSED" }
```

### 3.11 协议同意记录（详见 14 文档）

`POST /v1/agreements/consent`

请求：
```json
{
```

## 4. 支付方式枚举

| method | 说明 | 银联 msgType 映射（见 04 文档，已确认） |
|---|---|---|
| WECHAT | 微信支付（APP 原生） | **wx.unifiedOrder**（已确认） |
| ALIPAY | 支付宝（APP，跳支付宝小程序） | **trade.appPreOrder**（已确认）；间连场景 trade.precreate |
| UNIONPAY_CARD | 银行卡/云闪付（借记/贷记不区分） | **uac.appOrder（已确认）**：拉起银联统一收银台；成交卡种以银联回传 cardAttr 记录 |
| SCAN | 线下扫码（B 扫 C/C 扫 B） | **二期预留**：一期仅枚举占位，通道抽象预留 Native 扫码收单接口位，试点物业前台扫码二期启用 |

> 银行卡支付（借记/贷记）= **银联统一收银台**（msgType uac.appOrder，用户可选择云闪付及部分银行 APP，需已安装对应 APP）；银联答复"无直接选银行卡方式，绑卡属其他产品"。
> SCAN 为一期**枚举预留**（不下发、不收单），二期实现。

## 5. C 端对接时序（无收银台直驱，关键）

```
1. APP 调 3.9 商户支付方式查询 → 原生页面渲染可用支付方式（微信/支付宝/银联卡）
2. 业主选定支付方式 → APP 调 3.2 创建支付单（携 pay_method）→ 得 pay_params
3. APP 将 pay_params 传入银联 App 支付 SDK → 直接调起微信/支付宝/银联收银页
4. 业主完成支付 → 银联跳回 return_url → APP 回到支付结果页
5. APP 调 3.3 支付单查询确认状态（成功/失败/处理中）
6. 银联异步通知 → 支付中心更新状态 → 回调业务系统 notify_url（B 端回写账单）
7. 支付中心回调后，APP 刷新缴费记录（或 APP 自行调 3.3 兜底）
```

**关键点**：支付结果以"银联异步通知 + 支付中心回调"为最终依据；APP 跳回后的状态展示仅作即时反馈，**最终状态一律以 3.3 查单/回调为准**。

## 6. 对接联调检查单

- [ ] 创建支付单幂等：同 biz_order_no 重复请求返回原单（code=2003）
- [ ] 金额校验：items 合计 ≠ total_amount 时拒绝
- [ ] 支付方式开关：停用某支付方式后，3.9 查询不返回该项（C 端不展示）
- [ ] 回调重试：业务系统返回非 0000，支付中心按 5 次指数退避重试
- [ ] 回调验签：X-Sign 校验失败丢弃（记录告警）
- [ ] 退款：全额退款成功 → 原路退回 → 回调 REFUND_SUCCESS
- [ ] 重复通知：同一 notifyId/支付单重复通知不重复入账
- [ ] 状态时效约定：B 端账单"已缴"以支付中心回调为准（重试最长 ~16 分钟）；B 端可主动调 3.3 查单兜底，**禁止以银联直查结果直接入账**
- [ ] 商户收款查看：B 端按日汇总/明细与支付中心流水核对一致（3.10 交易查询）
- [ ] **pay_method 必填校验**：缺 pay_method 或非 3.9 可用项 → 1001/2002
- [ ] **pay_params 透传**：app_pay_request 原样返回，C 端 SDK 调起成功（联调时验证）
- [ ] **账单并发锁定**：同一 biz_bill_no 在 WAIT_PAY/PAID 时再次下单 → code=2004
- [ ] **退款状态校验**：WAIT_PAY/REFUNDING 原单发起退款 → code=3004
- [ ] **notify_url 白名单**：非白名单域名下单 → 拒绝
- [ ] **金额上限**：超商户限额 → code=2005
- [ ] 退款失败回滚：退款失败后原支付单回 PAID，可再次发起
