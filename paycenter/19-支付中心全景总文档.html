一、系统架构层级图 对应 01 §3

六层架构：调用方（业主/C 端 APP/物业人员/物业工作 APP·B 端）→ 接入层（支付参数下发 pay_params + 统一 OpenAPI 12 接口）→ 支付中心核心（交易核心 + 商户与协议）→ 存储层（MySQL 8 张一期表 + 二期表预留）→ 通道抽象层（银联一期 + 易宝/通联二期切换）→ 外部通道。
一期交付（蓝）· 二期预留（琥珀）· 红色虚线为调用关系；横切：签名验签/监控告警/幂等防重/脱敏/审计。

二、业主缴费主流程 · 系统交互泳道图 v1.1 直驱

4 列泳道（业主 C 端 APP / 支付中心 / 银联商务 / B 端系统）× 15 步时序。红色箭头表示下一步的归属系统。
无收银台链路：C 端原生选支付方式 → 下单（3.2 携 pay_method）→ 支付中心调银联 app/pay → 返回 pay_params → C 端银联 SDK 调起 → 业主完成支付 → 回跳查单（3.3）→ 支付中心收通知 → 回调 B 端。
关键兜底：银联通知丢失 → 支付中心超时查单任务（FR-15）补捞；UNKNOWN 一律查询收敛，严禁直接判失败。

三、退款流程 · 系统交互泳道图 退款流程

一期由 B 端/运营发起全额退款（C 端申请入口二期）。退款状态 UNKNOWN → 调 app/refund-query 兜底（5s/30s/60s/5min）；退款失败 → 原支付单回 PAID 可重试；已结算退款按比例返还手续费（refund_fee_return 记录）。

四、订单关闭 / 超时 / 兜底 · 系统交互泳道图 v1.1 直驱

C 端 APP 倒计时归零或用户取消 → 调关闭支付单（02 §3.8）→ 银联 order-close（尽力而为）→ 本地置 CLOSED。用户调起支付后中断（杀进程/切后台未回）→ 支付中心超期关闭任务兜底（超 expire_time 自动关闭）。

关键交互约束：

- 幂等：创建支付单按 biz_order_no；退款按 biz_refund_no；重复请求返回原单
- 防重复缴费：同账单有 WAIT_PAY/PAID/REFUNDING 单时拒绝新下单（2004）
- 结果确认：前端跳回传参不可信，一律查单（3.3）；最终一致靠支付中心回调
- 状态收敛：银联 UNKNOWN -> 查询兜底；严禁直接判失败
- 关闭/退款并发：支付单 PAID 后不可关闭；WAIT_PAY 不可退款（3004）
- SDK 结果码 0000 仅表示支付请求已发送，支付结果以通知/查单为准（04 §11）
