## 一、已确认的核心决策（v1.0 基线，改动需走变更评审）

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 业主缴费入口 | **APP 为主**：首筑物业 C 端 APP 原生支付组件，**直驱银联 SDK 调起微信/支付宝/银联统一收银台**（无自建收银台）；微信走 APP 支付通道（费率 0.65% 起，见 05 文档阶梯表） |
| 2 | 收银台形态 | **不做自建收银台（已取消，2026-08-18 确认）**：支付方式选择、金额展示由 C 端 APP 原生实现；支付中心仅下发银联支付要素 pay_params，C 端用银联 SDK 调起；小程序/H5 入口二期评估 |
| 3 | 资金流（一期） | 业主 → 银联 → **全额结算至物业公司**（T+N 到物业对公账户）；首筑佣金走线下结算 |
| 4 | 分佣预留 | **接口保留分账字段**（satInfo / divisionFlag / feeBear），一期不启用分账，二期可无缝切换 |
| 5 | 手续费 | **手续费参与分账设计**：手续费优先从交易金额中扣除后，剩余按规则处理；接口透传 feeBear 等字段 |
| 6 | 停车费一期边界 | **只做月租续费**（固定账单）；临停/无感支付/动态计费一期不做，预留代扣接口位 |
| 7 | 微信支付 | **银联子商户模式**：首筑通过银联商务在微信侧申请商户号；每家物业公司作为子商户（subAppId / isSubMchntPay=02）；测试号已有 |
| 8 | 账单来源 | 首筑 B 端物业系统（物业公司配置账单）→ C 端展示 → 支付 → 回写 B 端 |
| 9 | 多物业公司 | 物业公司 = N 个独立商户主体，逐一与银联、首筑签约入网；支付中心按商户配置化管理 |
| 10 | 重庆合规 | 前期物业费政府指导价、停车费按车位个数计费、收费明码标价公示、公共收益半年公示（若涉共有车位经营）；逾期催缴走书面催交→诉讼/仲裁 |
| 11 | 灰度上线 | 一期上线后**先 1 个试点物业 → 观察 1 周 → 全量**（D11-D16） |
| 12 | 发票一期 | C 端缴费结果页/记录页展示"如需发票请联系物业"指引；电子发票对接二期 |
| 13 | 商户收款查看 | 一期 B 端提供**按日收款汇总/明细**（资金流闭环对商户侧不缺失）；完整对账单二期 |
| 14 | 通道分润（已确认） | 银联费率明细表注明"**扣率为结算底价，超过部分 90% 结算给代理商（需开发票）**"——首筑作为代理商按交易量获得底价以上 90% 分润；**政策已确认，商务落实结算流程与开票**（比线下分佣合规可规模化） |
| 15 | 通道策略 | **一期仅银联商务一个真实通道**；易宝/通联/汇付/宝付**一期不对接，二期接入**——二期用途=**支付渠道切换**（银联故障时通过开关切换到备选通道）；通道抽象与切换开关一期设计，切换目标二期实现 |
| 16 | 首筑现有支付参数 | 首筑主体的银联商户号与微信子商户申请资料已提交银联商务，**开发/测试联调用现有测试参数；生产微信子商户参数待正式生效后另行下发**（具体凭据不进文档） |
| 17 | 协议范本已具备 | 全民付"线上购物车"服务协议（两方，银联商务重庆分公司，联系人周巾晶 18223034687）+ 银联商务特约商户支付业务申请书 V4.0 + 从业机构子APP支付权限申请表——**D1 起按范本推进首筑与银联签约** |
| 18 | 双公司主体 | 首筑网络技术(重庆)（支付/物业主体）+ 西藏首筑智选电子商务有限公司（智选 APP 主体）——商户/协议主体归属需与银联确认 |
| 19 | 线下扫码支付 | **二期实现**，一期**保留接口位**（通道抽象预留 Native 扫码收单、支付方式枚举预留 SCAN）——试点物业前台扫码缴费二期启用 |
| 20 | 多小区商户号（多样性） | 支持 **1 物业 1 商户号 / 1 小区 1 商户号 / 混合** 三种情况并存——用"商户-小区关联表（merchant_project）"承载映射，一期建表、二期扩展 |
| 21 | 接口组合（银联答复） | 下单走 `app/pay`；**查询/退款/退款查询统一走 `online/query`、`online/refund`、`online/refund-query`**（小程序/公众号场景可通用） |
| 22 | 支付方式 msgType（银联答复） | 微信原生=`wx.unifiedOrder`；支付宝=`trade.appPreOrder`（跳小程序）；**银行卡（借记/贷记）=`uac.appOrder` 拉起银联统一收银台**（银联答复：无直接选银行卡方式）；云闪付=`uac.appOrder` |
| 23 | SDK 已提供 | **银联商务全民付 APP 支付 SDK V3.1.8**（Android aar/iOS a/鸿蒙 har + 技术文档 V1.1.7）——P1 关键路径解除；集成要点见 04 §11 |
| 24 | 测试环境策略（银联答复） | **微信/云闪付无测试环境，走生产联调**；支付宝测试环境参数共用可能不稳；APP 支付宝需白名单时提供公网 IP（约 2 天加好） |
| 25 | 结算周期/退款/对账（银联答复） | 结算**默认 T+1**；退款时限**最大 360 天**且**返还手续费**；对账文件**走 FTP**（客户经理开通后提供账户密码） |
| 26 | 借记/贷记不分开（2026-10-19） | 支付方式合并为 `UNIONPAY_CARD`（银行卡/云闪付，uac.appOrder），去掉贷记卡开关；成交卡种按银联回传 `cardAttr` 落 txn_flow 计费率 |
| 27 | 技术栈（2026-10-19） | **JeecgBoot**（Spring Boot + Vue3）单体，按模块拆 pay-openapi / pay-channel / pay-core / pay-admin；操作后台复用 Jeecg 登录、角色、操作日志，与 OpenAPI 鉴权分离；同域子路径部署 |
| 29 | 不做 Mock 通道（2026-10-19） | 开发联调直接接银联测试环境（测试商户参数由 PM 提供，走本地配置不进文档/对话）；C 端联调依赖 D3 测试环境打通；异常类验收用例人工构造 |
| 28 | 开工前文档冲突收敛（2026-10-19） | 18 项冲突与银联问题的决策见 **23 文档**；已回写 01/02/04/05/14/20/21/22 |

## 三、一期范围（v2.0，按 2 周对接上限）

> **一期**：支付中台 API（创建支付单[pay_method 必填，返回银联支付要素]/查单/关闭支付单/退款/退款查/业务回调/交易查询/商户支付方式）+ 银联 APP 通道对接 + 交易核心（状态机/幂等/流水[含手续费/结算日]/超时查单任务/账单在途锁定）+ 商户配置（最小）+ **C 端原生支付组件直驱银联 SDK（无收银台）** + C 端单账单缴费（账单/选方式/下单/调起/结果/记录/**发票指引**）+ B 端账单回写 + **B 端按日收款查看（最小）** + 首筑操作后台 MVP（20 文档）。**完整验收级清单见 08 文档（A-H 41 项）。**
> **二期**：对账中心、费率体系、三级开关后台、运营后台完整版、退款审核流、多账单合并、分账启用、小程序/H5 入口、汇付通道、临停/无感代扣、商户自助、催缴/公示、电子发票对接、部分退款、存量支付迁移评估。
> 详见 08-功能两期拆分.md。
