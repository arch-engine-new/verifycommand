## 1. 定位与边界

**三个端口的职责划分（先分清，避免做重）：**

| 端口 | 使用方 | 视角 | 职责 |
|---|---|---|---|
| **操作后台（本文件）** | 首筑运营/管理员 | **平台全局**（所有物业公司） | 商户配置、退款处理、交易查询、开关、留痕、异常处理 |
| B 端物业系统 | 单个物业公司 | **本物业**（自己小区） | 账单配置、收款查看（消费支付中心回调/3.10 交易查询） |
| C 端 APP | 业主 | 本人 | 账单、缴费、记录 |

**一期核心原则**：
- 操作后台是**支付中心自带的运营端**，不并入 B 端物业系统（决策记录 E：独立最小后台）
- 一期只做"能干活"的极简后台——商户配置、退款处理、交易查询是**硬必需**（没有界面，运营无法配置商户、无法处理退款、无法查单），其余从简
- 权限最小化：一期 2 个角色，不做复杂 RBAC

## 2. 角色与权限（一期）

| 角色 | 范围 | 可用页面 | 关键权限 |
|---|---|---|---|
| **管理员**（首筑超管） | 全部 | 全部 7 页 | 商户配置增改、商户启停、支付方式开关、单笔限额修改、账号管理 |
| **运营**（日常操作） | 全部（只读为主 + 退款操作） | 工作台/商户管理（只读）/交易查询/退款处理/协议留痕/操作日志 | 退款发起与重试、查单；**商户配置只读**（改配置需管理员） |

> 二期扩展：财务（结算/对账视图）、客服（只读）、按商户数据权限隔离（运营只管部分物业公司）。

**账号体系**：一期操作后台独立账号（手机号+密码+验证码，管理员在后台建号）；二期接入首筑统一登录。
**实现口径（技术栈 JeecgBoot，2026-10-19 定）**：复用 JeecgBoot 自带登录（图形验证码、失败锁定、JWT）、用户/角色权限与系统操作日志；登录名用手机号；按本文配置「5 次失败锁 15 分钟」「token 24h」；管理员、运营建为两个 Jeecg 角色。与业务系统 OpenAPI 鉴权（app_id + app_secret 换 Bearer 2h）完全分离。界面采用 JeecgBoot Vue3（Ant Design Vue）风格，21 号原型仅作页面结构、字段与交互依据。

## 4. 页面功能明细

### P1 登录页
- 手机号 + 密码 + 图形验证码；登录失败锁定（5 次锁 15 分钟）
- 登录后签发管理 token（有效期 24h，与业务 OpenAPI 的 access_token 隔离）

### P2 工作台（概览）
- 今日：支付成功笔数/金额、退款笔数/金额、待处理退款数、UNKNOWN 待核查数（来自超时查单任务告警）
- 通道健康：银联通道连通性（最近一次下单/查询成功率，后端探活）
- 快捷入口：待处理退款 → 退款处理页

### P3 商户管理（核心页）
**列表**：商户编码/名称、关联小区数、状态（启用/停用）、支付方式开关状态（微信/支付宝/银行卡 三色标签）、银联商户号末 4 位、操作（编辑/启停）
**新增/编辑表单**（对应 merchant 表 + merchant_project 表）：
| 字段 | 说明 |
|---|---|
| 商户编码 merchant_code | 唯一，如 WY001 |
| 商户名称 | 物业公司全称 |
| 银联商户号/终端号 | 银联开户后填入 |
| 微信子商户 subAppId | 银联下发后填入（未批留空=微信自动禁用） |
| 回调地址 callback_url | 支付结果回调（须与 notify_domain 白名单一致） |
| notify_domain 白名单 | 防回调地址篡改 |
| 支付方式开关 | 微信/支付宝/银行卡（云闪付） 3 个 enabled（借记/贷记不分开） |
| 单笔限额 max_amount | 默认 50000.00 元 |
| 手续费承担方 fee_bearer | 商务约定 |
| 关联小区 | merchant_project 列表（支持 1 物业多小区/1 小区 1 商户/混合） |
| 状态 | 启用/停用（停用=拒绝新单，在途单不受影响） |

**关键交互**：修改支付方式开关或状态后**立即生效 ≤30s**（缓存失效），C 端支付方式页按最新配置展示（3.9 查询结果变化）；每次修改写操作日志。

### P4 交易查询
- 查询条件：支付单号/业务单号/退款单号、商户、支付方式、状态、时间范围（默认今天，最长 90 天）
- 结果：支付单列表（单号/商户/金额/方式/状态/时间）→ 详情（含 items 账单明细、银联流水号、手续费、结算日）
- 退款单可联动查看；支持导出 CSV（二期对账单再上）
- **数据源**：管理查询接口（复用 02 §3.10 交易查询 + 支付单详情查询）

### P5 退款处理（一期退款的操作入口）
- **退款列表**：退款单号/原支付单/商户/金额/状态（REFUNDING/SUCCESS/FAIL/UNKNOWN）/时间，筛选 + 分页
- **发起退款**：输入/选择支付单号 → 显示原单信息（金额/已退金额/可退金额）→ 填退款金额（一期仅全额）与原因 → 提交（调 02 §3.4 创建退款单）
- **重试**：退款 FAIL 或 UNKNOWN 的单可手动重试（UNKNOWN 先自动调银联退款查询兜底，仍未知才允许重试）
- **状态兜底**：UNKNOWN 单进入"待核查"列表，运营按流程处理（调银联查询/联系银联）
- 一期退款由运营在**本页**或 B 端发起（C 端申请入口二期）

### P6 协议留痕查询
- 按 user_id/手机号查：已同意的协议清单（agreement_code、版本、时间、来源、device_id）
- 只读，供法务/客服响应争议

### P7 操作日志
- 记录：登录、商户增改/启停、开关变更、限额变更、退款发起/重试、协议配置变更
- 字段：操作人、动作、对象、变更前后值（JSON diff）、时间、IP
- 查询：按操作人/时间/对象筛选；保留 ≥5 年

## 9. 页面交互逻辑（配套可交互原型：`21-操作后台HTML原型.html`，浏览器直接打开可点）

> 原型覆盖 7 页 + 角色切换（管理员/运营）+ 商户编辑/启停/开关 + 退款发起/重试 + 详情弹窗，全部为演示数据；开发时替换为真实接口（A1-A12，见 §5）。

### 9.1 全局交互

| 交互 | 规则 |
|---|---|
| 登录 | 手机号+密码+图形验证码；**连续失败 5 次锁定 15 分钟**；登录签发管理 token（24h，与业务 OpenAPI 隔离） |
| 角色 | 管理员：全功能；运营：商户配置**只读**（新增/编辑/启停按钮禁用或点击提示"需管理员权限"），可查单/退款/重试 |
| 导航 | 左侧 6 菜单（工作台/商户管理/交易查询/退款处理/协议留痕/操作日志），切换即刷新 |
| 反馈 | 操作成功/失败统一 toast（2s 自动消失）；确认类操作（启停/重试）一律弹 confirm 二次确认 |
| 错误码 | 后端错误按 10 文档映射为用户文案，不裸奔错误码 |

### 9.2 P2 工作台

- 加载：调 A10 今日概览统计 + 通道健康探活
- 4 张指标卡：今日支付成功（笔数/金额）、今日退款、待处理退款数、**UNKNOWN 待核查数**（超时查单任务告警来源）
- 待处理退款/UNKNOWN 卡点击 → 跳转退款处理页（带状态筛选）；通道健康异常时卡变红并提示
- 快捷入口：去处理 → 退款处理页

### 9.3 P3 商户管理（核心交互）

**列表**：加载调 A2（商户列表/详情）；展示商户编码/名称、关联小区数、状态、支付方式三色标签（微信/支付宝/银行卡，绿=开/红=关）、银联商户号末 4 位、操作（编辑/启停）。

**编辑流**（管理员）：点"编辑" → 弹窗回显商户配置（merchant 表 + merchant_project）→ 改字段 → 保存（调 A3/A4/A5）→ **写操作日志** → toast"已保存，支付方式开关 ≤30s 生效"。
**新增流**：点"新增商户" → 空表单（商户编码唯一性校验、必填项校验）→ 保存。
**启停流**：点"停用/启用" → **confirm 二次确认**（提示"停用=拒绝新单，在途单不受影响"）→ 确认后调 A3 → 写日志 → 状态列即时刷新。
**开关即时生效**：修改支付方式 enabled 保存后，**≤30s**（缓存失效）C 端支付方式页按 3.9 新结果展示——运营需知道这一时效口径。

### 9.4 P4 交易查询

- 筛选区：单号（支付/业务/退款）、商户、支付方式、状态、时间范围（默认今天，**最长 90 天**）
- 查询：调 A6/A7 → 列表（单号/商户/金额/方式/状态/时间）分页
- 详情：点行 → 弹窗展示 items 账单明细、银联流水号、手续费、结算日；退款单可联动跳转退款处理页
- 导出 CSV：二期（对账单二期上）
- 状态口径提示：**以支付中心回调/查询为准**，UNKNOWN 单引导去退款处理页核查

### 9.5 P5 退款处理（一期退款操作入口）

**发起退款 3 步**（核心交互）：
1. 输入原支付单号 → 点"回显原单"（调 A6）→ 显示原单信息（金额/已退/可退，一期仅全额）
2. 填退款金额（**校验 = 可退金额**）与原因（必填）
3. 提交（调 A8 创建退款单）→ toast"退款已提交" → 列表置顶显示 REFUNDING → 写操作日志

**重试**：FAIL/UNKNOWN 单显示"重试"按钮 → confirm（提示"UNKNOWN 单先自动调银联退款查询，仍未知才允许重试"）→ 调 A9 → 刷新状态。
**UNKNOWN 处理**：列表顶部黄色警示条（"有 N 笔 UNKNOWN 退款待核查"）→ 运营按流程：先自动查单兜底（5s/30s/60s/5min）→ 仍未知联系银联（04 §13）。

### 9.6 P6 协议留痕

- 输入 user_id/手机号 → 调 A11 → 展示已同意协议清单（agreement_code/版本/时间/来源/device_id）
- 只读，供法务/客服响应争议；无记录显示空态

### 9.7 P7 操作日志

- 加载：调 A12（操作日志列表）；筛选：操作人/动作（登录/商户新增/编辑/启停/开关变更/退款发起/重试）/时间
- 列表：操作人、动作、对象、**变更前后值（JSON diff）**、时间、IP；保留 ≥5 年

## 10. 开放项（需确认）

1. **操作后台部署形态**：与支付中心服务同域独立管理子域（建议，如 `admin.pay.xxx`），还是独立部署？—— 建议同域子路径，避免多一套部署运维
2. **登录方式**：一期独立账号（建议）还是直接接首筑现有 SSO？如有现成 SSO 可省开发
3. **P2 工作台是否一期**：建议做（运营每天要看），若排期紧可砍到二期，不影响"能干活"
4. **操作日志保留策略**：≥5 年（与支付机构留存要求一致），是否够？
