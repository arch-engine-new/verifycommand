# 14 · 用户协议与前端交互设计（业主侧）

| 版本 | v1.0 |
|---|---|
| 日期 | 2026-08-18 |
| 用途 | 明确 C 端业主需要签署/知悉的协议清单、前端交互方式、版本管理与留痕 |
| 原则 | ①每份协议只在"首次触达"时强校验一次，后续展示入口即可 ②所有同意行为留痕（用户ID+协议版本+时间）③法务文本由首筑法务提供，本文件只定交互与清单 |

---

## 1. 协议清单（业主侧）

**协议主体关系（先定谁跟谁签，避免签错）**：
- **业主侧（C 端）**：只签**首筑的协议**——《用户服务协议》《隐私政策》《支付服务说明》（即"支付服务协议"，内容为：支付服务由持牌机构银联商务提供、清算路径、退款规则、争议处理，并以链接引用银联/微信/支付宝条款）
- **银联商务协议（全民付"线上购物车"服务协议、特约商户收单协议）= B 端**（银联↔首筑、银联↔物业公司），**业主不签**
- **微信/支付宝协议**：用户使用渠道时已同意，拉起支付自动适用，**首筑不重复让业主签**

| # | 协议 | 签署主体 | 触发场景 | 强校验（首次） | 展示入口（之后） | 法务文本 |
|---|---|---|---|---|---|---|
| 1 | 用户服务协议 | 首筑 | 首次注册/登录 APP | ✅ 勾选同意才能继续 | 我的→设置→关于 | 首筑法务 |
| 2 | 隐私政策 | 首筑 | 首次注册/登录 APP | ✅ 勾选同意（可与 1 合并勾选） | 我的→设置→关于 | 首筑法务 |
| 3 | 支付服务说明（支付服务协议） | **首筑**（内容引用银联/微信/支付宝条款） | **首次发起支付** | ✅ 弹窗确认"我已阅读并同意" | C 端支付方式页/支付结果页"支付服务协议"入口（无收银台，入口在 APP 原生页面） | 首筑法务 + 引用银联/渠道条款 |
| 4 | 物业缴费须知（电子账单服务说明） | 首筑（内容与物业确认） | 首次进入缴费页/查看账单 | ⚠️ 页面顶部横幅展示即可，无需勾选 | 账单页"缴费须知"入口 | 首筑 + 物业确认 |
| 5 | 退款规则说明 | 首筑 | 首次申请退款（二期 C 端退款入口） | ✅ 确认"已知悉退款时效与原路退回规则" | 退款页说明区 | 首筑法务 |

> 一期只做 **1/2/3**（用户协议、隐私政策、支付服务说明）；4（缴费须知）以横幅展示；5（退款规则）随二期退款申请入口。
> 待确认：银联商务是否有面向消费者的必展示条款（"全民付"用户协议），如有，在《支付服务说明》中以链接纳入——已列入 04 银联待确认清单。

## 2. 前端交互设计

### 2.1 用户服务协议 + 隐私政策（注册/登录时）

```
首次登录
  ├─ 弹层：协议勾选卡
  │    [ ] 我已阅读并同意《用户服务协议》
  │    [ ] 我已阅读并同意《隐私政策》
  │    （协议文字为链接，点击弹出全文页）
  ├─ 未勾选 → [登录] 置灰不可点
  └─ 已勾选 → 记录留痕（userId + 协议id + 版本号 + 时间）→ 进入 APP
后续登录：不再弹出（留痕判断），仅"我的→设置→关于"可查看
```

### 2.2 支付服务协议（首次支付时）

```
用户首次点击 [立即支付]（支付中心判断该用户无支付协议留痕）
  ├─ 弹窗（半屏）：
  │    《支付服务协议》全文概要 + 链接
  │    [ ] 我已阅读并同意《支付服务协议》
  │    [ 取消 ]  [ 同意并支付 ]
  ├─ 同意 → 支付中心记录留痕（biz_user_id + 协议版本 + 时间）→ 继续调起支付
  └─ 取消 → 返回支付方式页，不调起支付
后续支付：有留痕 → 直接调起，不再弹窗；支付方式页/结果页保留协议入口
```

**留痕接口**（支付中心提供，供 C 端调用）：
- `POST /v1/agreements/consent`（记录同意：user_id、agreement_code、version）
- `POST /v1/agreements/status`（查是否已同意某协议；body：user_id、agreement_code、version，以 02 §3.12 为准）
- 数据表：`user_agreement_consent（id、user_id、agreement_code、version、consent_time、source）`

### 2.3 缴费须知（账单页横幅）

```
账单列表/详情页顶部（非阻塞）：
  ⚠ 缴费须知：缴费即视为同意按物业公示的收费标准缴纳；电子账单与纸质通知具有同等效力。
  [查看详情] → 须知全文页（含：收费项目公示、发票获取方式、退款规则摘要）
```

### 2.4 退款规则（二期，退款申请时）

```
用户申请退款 → 弹窗：
  退款将原路退回：微信零钱/支付宝余额即时到账，银行卡 0-3 个工作日；
  退款金额以原支付单为准，全额退款。
  [ ] 我已了解上述退款规则
  [ 取消 ]  [ 提交申请 ]
```

## 3. 协议版本管理

| 项 | 规则 |
|---|---|
| 版本号 | 格式 v1.0 / v1.1；法务文本变更 → 版本递增 |
| 变更生效 | 新版协议发布后，**首次触达的用户重新弹窗同意**（老用户不追溯，但展示"协议已更新"提示） |
| 文本存储 | 协议全文由支付中心/内容系统托管（URL 化），前端只存版本号与链接 |
| 留痕查询 | 客服可查某用户的协议同意记录（audit） |

## 4. 与现有文档的衔接

- C 端 APP 支付方式页/结果页"支付服务协议（点击查看）"入口（无收银台，入口在 APP 原生页面）
- 首次支付弹窗逻辑挂在"立即支付"前置：**02 §3.2 创建支付单**之前由 C 端完成协议确认（或支付中心在创建支付单时校验该用户协议留痕，未同意返回专用错误码，由 C 端引导弹窗）
- 建议支付中心在创建支付单接口增加校验：`user_agreement_required`（用户未同意支付协议 → 返回 4001 协议未确认），由 C 端弹窗 → 调留痕接口 → 重新下单——**防绕过**

## 6. 埋点与落库明细（点击动作 + 确认留痕）

### 6.1 埋点事件（点击/行为，前端埋点 SDK，事件名 `agreement_*`）

| 事件 | 触发 | 上报参数 | 用途 |
|---|---|---|---|
| agreement_expose | 协议弹窗/横幅展示 | user_id、agreement_code、version、source(LOGIN/PAY_APP/BILL_PAGE) | 曝光统计 |
| agreement_click_view | 点击"查看全文/协议链接" | 同上 + entry(弹窗/底部链接/设置页) | 协议触达分析 |
| agreement_consent | 勾选同意并提交 | user_id、agreement_code、version、source | **权威留痕（双写：埋点+落库）** |
| agreement_reject | 点击取消/拒绝 | 同上 | 流失分析 |

### 6.2 落库设计（权威数据）

**库**：**支付中心数据库**（与 pay_order 同实例）。理由：支付协议校验发生在"创建支付单"时，同库保证校验一致性与事务性；用户协议/隐私政策同意也统一落此库，C 端/B 端统一查询。

**表 1：`user_agreement_consent`（同意记录，权威，法律证据）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK 自增 | |
| user_id | varchar(64) | 业主标识 |
| agreement_code | varchar(32) | 协议编码：USER_SERVICE/PRIVACY/PAY_SERVICE/FEE_NOTICE/REFUND_RULE |
| version | varchar(16) | 协议版本（v1.0） |
| consent_time | datetime | 同意时间（权威时间戳，服务端生成） |
| source | varchar(32) | LOGIN / PAY_APP / BILL_PAGE / REFUND |
| client_ip | varchar(45) | 审计 |
| device_id | varchar(64) | 设备标识（可选） |
| created_at / updated_at | datetime | |

索引：**唯一索引 uk(user_id, agreement_code, version)**；普通索引 idx(user_id)、idx(agreement_code)

**表 2：`agreement_event_log`（点击/查看/拒绝埋点流水，审计辅助）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| event | varchar(32) | expose / click_view / consent / reject |
| user_id | varchar(64) | |
| agreement_code | varchar(32) | |
| version | varchar(16) | |
| entry | varchar(32) | 触发入口 |
| client_ip | varchar(45) | |
| device_id | varchar(64) | |
| created_at | datetime | |

索引：idx(created_at)、idx(user_id)

### 6.3 数据流与防绕过（校验闭环）

```
C 端 点立即支付
  → 支付中心创建支付单前校验：查 user_agreement_consent（user_id + PAY_SERVICE + 当前版本）
      无记录 → 返回 4001 协议未确认
  → C 端弹窗 → 用户同意 → POST /v1/agreements/consent（事务：写 consent 表 + 埋点）
  → 重新调创建支付单 → 校验通过
```

- 校验在**支付中心服务端**做（不能只靠前端），4001 防绕过
- 同意接口幂等：同一 (user_id, agreement_code, version) 重复提交不重复插入

### 6.4 保留策略与存储

| 数据 | 保留 | 存储 |
|---|---|---|
| user_agreement_consent | **永久**（法律证据，涉消保/仲裁） | 支付中心 MySQL 业务库 |
| agreement_event_log | **≥5 年**后归档（参考支付机构交易记录留存要求） | MySQL，量大迁 ES/归档表 |

> 合规依据：《非银行支付机构监督管理条例》交易记录留存要求 + 消费者权益保护（协议同意为重要证据）。
