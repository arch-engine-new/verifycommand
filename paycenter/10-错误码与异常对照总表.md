## 1. 我方内部错误码（业务系统对接，02 §1.3 完整版）

| code | 说明 | 可重试 | 处理动作 |
|---|---|---|---|
| 0000 | 成功 | — | — |
| 1001 | 参数错误 | 否 | 调用方修正请求 |
| 1002 | 鉴权失败（签名/密钥错误） | 否 | 检查 app_id/app_secret/签名 |
| 1003 | token 过期或无效 | 是 | 重新获取令牌 |
| 2001 | 商户未配置或已停用 | 否 | 联系运营配置商户 |
| 2002 | 支付方式未开通（开关关闭） | 否 | 运营开开关 或 换支付方式 |
| 2003 | 业务单号已存在（幂等返回原单） | — | 取 data 原单信息，不重复下单 |
| 2004 | 账单存在进行中的支付单（同 biz_bill_no 已有 WAIT_PAY/PAID/REFUNDING 单） | 否 | 提示"该账单正在支付/已缴费" |
| 2005 | 金额超限（超过商户/通道单笔限额） | 否 | 拆单或联系运营调限额 |
| 3001 | 支付单不存在 | 否 | 核对单号 |
| 3002 | 支付单状态不允许该操作 | 否 | 按状态机走 |
| 3003 | 退款金额超限 / 不可退 | 否 | 核对可退金额 |
| 3004 | 原支付单状态不允许退款（非 PAID） | 否 | 按状态机走 |
| 4001 | 协议未确认（用户未同意当前版本《支付服务说明》） | 否 | C 端弹窗引导确认后重试（与 02 §1.3 一致） |
| 5001 | 通道异常（可重试） | 是 | 指数退避重试 ≤3 次 |
| 9999 | 系统繁忙 | 是 | 退避重试；持续则告警 |

## 2. 银联错误码映射（银联 → 我方 → 用户文案）

> ⚠️ **出处说明**：`respCode=0000` 与 status 枚举有银联 PDF 原文出处；**errCode=1001/1000/9200 的具体含义为联调惯例推断（非银联文档原文），D1 向银联索取官方错误码表核实**——代码按"非 0000 一律进查询兜底"防御，不受具体含义影响。

| 银联侧 | 我方 | 用户可见文案 | 处理 |
|---|---|---|---|
| respCode=0000 / errCode=0000 | 0000 | — | 正常（PDF 原文："0000为成功"） |
| errCode=1001 授权失败（appId 无对应交易权限）* | 5001 | "该支付方式暂不可用，请稍后重试" | 记日志+告警（配置问题，不重试） |
| errCode=1000 认证失败（签名/密钥/token 失效）* | 9999 | "系统繁忙，请稍后重试" | 记日志+告警（内部配置） |
| errCode=9200 系统繁忙（限流）* | 5001 | "支付通道繁忙，请稍后重试" | 退避重试 ≤3 次 |
| 其他非 0000 / 未知 | 5001 | "支付未完成，请稍后在缴费记录中确认" | 走查询兜底（FR-15） |
| status=UNKNOWN | WAIT_PAY+查单 | "支付结果确认中…" | 查询兜底，严禁直接判失败 |

\* = 联调惯例值，以银联实际返回为准（见上方⚠️）。

## 2.1 SDK 结果码映射（C 端调起层，银联 SDK 文档表 12 原文）

> **重要**：SDK resultCode 仅表示"支付请求发送结果"，**不代表支付结果**——0000 后仍需查单/回调确认；严禁以 SDK 回调直接入账。

| SDK resultCode | 含义（文档原文） | 我方处理 | 用户文案 |
|---|---|---|---|
| 0000 | 支付请求发送成功 | 查单/等通知确认 | "支付处理中…" |
| 1000 | 用户取消支付 | 支付单保持 WAIT_PAY 可重试 | "已取消支付" |
| 1001 | 参数错误（appid 未配置/三者不一致） | 记日志+告警（配置问题） | "支付配置异常，请稍后重试" |
| 1002 | 网络连接错误 | 提示重试 | "网络异常，请重试" |
| 1003 | 支付客户端未安装 | 引导安装（安卓 11 检查 queries 声明） | "未检测到微信/支付宝，请先安装" |
| 2001 | 订单处理中，结果未知 | 查单兜底 | "支付结果确认中…" |
| 2002 | 订单号重复 | 幂等处理 | "订单已存在，请勿重复支付" |
| 2003 | 订单支付失败 | 支付单保持 WAIT_PAY 可重试 | "支付未完成，请重试" |
| 9999 | 其他支付错误 | 提示稍后重试 | "支付失败，请稍后重试" |

## 3. 银联交易状态枚举 → 我方支付单状态

| 银联 status | 我方支付单 | 说明 |
|---|---|---|
| NEW_ORDER | WAIT_PAY | 新订单 |
| WAIT_BUYER_PAY | WAIT_PAY | 等待支付 |
| TRADE_SUCCESS | PAID | 支付成功（通知/查询收敛） |
| TRADE_CLOSED | CLOSED | 超时/关闭/支付失败类 |
| TRADE_REFUND | REFUNDING/REFUNDED | 转入退款流程 |
| UNKNOWN | WAIT_PAY+查单 | 未明确，走兜底 |

## 4. 银联退款状态枚举 → 我方退款单

| 银联 refundStatus | 我方退款单 | 说明 |
|---|---|---|
| SUCCESS | REFUND_SUCCESS | 退款成功（**以 SUCCESS 为准，任何未知值一律走退款查询兜底**） |
| FAIL | REFUND_FAIL | 退款失败，原支付单回 PAID 可重试 |
| PROCESSING | REFUNDING | 处理中，轮询兜底 |
| UNKNOWN | REFUNDING+查询 | 调退款查询收敛 |

## 5. 通知处理

| 场景 | 我方行为 |
|---|---|
| 银联通知验签失败 | 丢弃 + 告警（防伪造），不回 SUCCESS |
| 银联通知重复（同 notifyId/mchntOrderId） | 幂等，不重复入账，仍回 SUCCESS |
| 业务回调失败（非 0000） | 指数退避重试（1m/2m/4m/8m/16m 共 5 次） |
| 业务回调验签失败（X-Sign） | 丢弃 + 告警 |
