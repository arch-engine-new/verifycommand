## 1. 通道选型与切换策略

| 通道 | 模式 | 接入节奏 | 用途 |
|---|---|---|---|
| **银联商务** | 子商户（isSubMchntPay=02）+ 线上购物车分账 | **一期唯一真实通道** | 收单 |
| 易宝支付 | 微信渠道号 + 子商户实名认证 + 后台配分账比例 | **二期接入** | 通道切换备选 |
| 通联支付（ISV 服务版） | 云商通账户体系，ISV 不碰资金，订单抽佣 | **二期接入** | 通道切换备选 |
| 汇付 / 宝付 | 标准收单/询价 | 二期评估 | 通道切换备选 |

> **通道切换开关（接口一期就位）**：全局通道开关 + 商户支付方式开关（§4）即"切换开关"——银联故障时一键停用/降级；二期接入易宝/通联后通过同一开关切换，业务系统与 C 端无感（适配器模式，01 §3 扩展点）。

## 2. 计费模型（首筑收入视角）

| 收入类型 | 说明 | 实现 |
|---|---|---|
| 交易佣金（分账） | 从交易中按比例分佣（二期分账启用） | 商户费率表 + 分账 satInfo |
| 通道分润（服务商分润） | **政策已确认**：银联费率表注明"扣率=结算底价，超过部分 **90% 结算给代理商**（需开发票）"——首筑作为代理商按交易量获得底价以上 90% 分润 | 无需系统实现，银联侧结算+开票 |
| 订阅费（SaaS 系统费） | 物业公司使用 B 端系统的年费/月费（行业通行：支付宝物业方案=项目接入费+协作费） | 商户费率表加 SUBSCRIPTION 维度（二期） |

> 一期：交易佣金（分账字段预留）+ **通道分润（政策已确认，商务落实结算流程与开票）**；订阅费二期。

## 3. 费率体系（三张表，全部配置化）

### 3.1 通道费率表（channel_fee_rule）—— 银联阶梯报价（2026-08-18 变更单/费率明细表确认）

**线上 APP 端（我方一期场景）**：

| 年均交易量 | 微信 | 支付宝 | 借记卡 | 贷记卡 | 备注 |
|---|---|---|---|---|---|
| 0-1000 万 | **0.65%** | 0.30% | 0.30% | 0.60% | 首档（**修正：非 0.7%**） |
| 1000-2000 万 | 0.64% | 0.29% | 0.29% | 0.59% | |
| 2000-5000 万 | 0.63% | 0.28% | 0.28% | 0.58% | |
| 5000 万-1 亿 | 0.62% | 0.27% | 0.27% | 0.57% | |
| 1 亿以上 | 0.62% | 0.26% | 0.26% | 0.56% | |

**其他场景（二期参考）**：
- 小程序端微信：0.30%→0.26%（**注：物流类被微信认定为特殊行业，费率同 APP 端微信 0.65% 起**——物业缴费若涉快递代收需注意）
- H5/PC 端：微信/支付宝/借记卡 0.30%→0.26%，贷记卡 0.60%→0.56%
- 企业网银：10 元/笔
- POS 线下：借记卡 0.45% 单笔 20 元封顶→0.41% 封顶 18 元；贷记卡 0.60%→0.56%

> **分润政策（同表注明）**："以上扣率为结算底价，超过部分 90% 结算给代理商（需开发票）"——首筑对外报价与底价之差的部分，90% 归属首筑。
> **正式费率出处**：《变更单.docx》（首筑网络技术(重庆)，2026-08-18）与《费率明细表.xlsx》；写入 fee_rule 表（支持 tier_start/tier_end 阶梯结构）。
> **手续费计算规则（微信/支付宝通用）**：单笔订单金额 × 费率，四舍五入保留 2 位小数；结算时从应结金额扣除后入账。
> **退款手续费返还**：已结算退款按比例返还已收手续费（退款单记录 refund_fee_return）；未结算退款轧差计算。

### 3.2 商户费率表（merchant_fee_rule）
每个物业公司可单独约定费率（覆盖通道费率），支持：
- 按通道费率（默认，inherit）
- 自定义比例费率
- 固定费率（元/笔）

```json
{ "merchant_code": "WY001", "channel": "UNIONPAY", "pay_method": "WECHAT",
  "mode": "INHERIT" | "CUSTOM", "rate": "0.006", "fixed_fee": 0 }
```

### 3.3 阶梯费率表（tier_fee_rule）
支持按"自然月累计交易额"阶梯计价（为银联阶梯报价预留）：

```json
{ "channel": "UNIONPAY", "pay_method": "WECHAT",
  "tiers": [
    { "from": 0, "to": 20000000, "rate": "0.0065" },
    { "from": 20000000, "to": null, "rate": "0.0064" }
  ] }
```

### 3.4 手续费计算与承担（决策 #5）

```
手续费 = 交易金额 × 商户费率（或通道费率）
```

**承担方模型（对接银联 feeBear / 分账设计）**：

| 方案 | 说明 | 一期 |
|---|---|---|
| 分账优先扣 | 交易金额中优先扣手续费，剩余再分账（物业承担手续费） | 数据模型支持，satInfo/feeBear 字段透传（一期传空） |
| 首筑承担 | 手续费不扣物业，首筑贴成本（商务补贴场景） | 结算试算时以负数项体现 |
| 按商户约定 | 商户费率表配置承担方 | 配置项 |

一期实现：**手续费试算**（下单时估算、操作后台展示、结算单二期生成实算）；承担方由商务与物业约定，配置进商户表。

## 4. 通道开关（三级）

### 4.1 开关层级

| 层级 | 作用 | 示例 |
|---|---|---|
| 全局开关 | 通道/支付方式整体可用性 | 银联微信通道故障 → 全局关闭 WECHAT |
| 商户级开关 | 某物业公司可用支付方式（WECHAT / ALIPAY / UNIONPAY_CARD 三项；借记/贷记不分开） | 物业 A 微信未批 → C 端支付方式页不展示微信。银行卡借/贷费率按银联回传 cardAttr 计入 fee_amount |
| 支付方式级开关 | 单支付方式细粒度控制（灰度） | 微信子商户未批 → 微信隐藏，支付宝/银联卡照常 |

### 4.2 裁决逻辑（下单时服务端裁决）

```
pay_method 可用 = 全局开关(enabled)
              ∩ 通道健康(银联该方式可用)
              ∩ 商户配置(enabled)
              ∩ 支付方式级开关(enabled)
```

**C 端展示依据**：3.9 商户支付方式查询响应（服务端已裁决）；C 端不再二次判断。

### 4.3 通道降级（应急）

- 银联单支付方式故障：全局关闭该方式，C 端支付方式页自动不展示，**其他方式不受影响**
- 银联整体故障：C 端支付方式页提示"支付通道维护中"（一期无备用通道，不可自动切换；二期接汇付后走路由）
- 开关操作：操作后台一键操作，操作留痕，**生效 ≤30s（缓存失效）**

## 5. 结算试算（二期）

- 输入：某物业公司某时间段内支付/退款明细
- 输出：应收总额、手续费合计、预计到账净额（= 应收 - 手续费）
- 用途：运营/商务对账参考；二期升级为正式结算单（T+N 自动生成、与资金对账）

## 6. 对账（二期，L1 渠道对账先行）

### 6.1 对账分层

| 层 | 对什么 | 粒度 | 周期 | 实施 |
|---|---|---|---|---|
| L1 渠道对账 | 我方支付单/退款单 vs 银联清算文件 | 逐笔（单号/金额/状态） | 日 | 二期 |
| L2 商户对账 | 按物业公司聚合：收入/退款/手续费 | 商户 | 日/月 | 二期（依赖账务） |
| L3 资金对账 | 银行实际到账 vs 结算单 | 结算 | 日 | 二期 |

### 6.2 L1 渠道对账流程

```
每日定时任务（T+1 03:00）
  1. 拉取银联 T 日清算文件（FTP：客户经理开通后提供账户密码；集团对账单 30 列字段见 04 §12）
  2. 文件解析 → 明细入库（reconcile_file_detail）
  3. 我方口径：取 T 日支付成功/退款成功的本地支付单/退款单快照
  4. 逐笔比对：
     以 mchntOrderId（银联"商户订单号"）/ refundOrderId（"退货订单号"）为关联键
     比对维度：金额（交易金额/清算金额/手续费）、状态、发生日期
     手续费核对：银联"手续费"列 vs 我方 txn_flow.fee_amount
  5. 产出差异（reconcile_diff）→ 运营在操作后台核销
  6. 全平 → 对账任务标记完成
```

### 6.3 差异类型定义

| 差异类型 | 定义 | 处理 |
|---|---|---|
| LONG_PAY 长款（我方有、银联无） | 我方支付单成功，银联文件无该笔 | 核查：通知丢失+查询兜底失败；确认无该笔→银联查单/人工核查；必要时标记可疑冻结 |
| SHORT_PAY 短款（银联有、我方无） | 银联文件有，我方无对应支付单 | 高优先级：可能漏单/参数错乱；按 mchntOrderId 反查本地，无则人工核对是否其他业务系统交易 |
| AMOUNT_DIFF 金额不平 | 单号一致金额不一致 | 冻结差异，人工核查（可能部分退款、优惠、手续费冲正） |
| STATUS_DIFF 状态不一致 | 如我方已退款，银联文件仍显示支付成功 | 复核退款状态 |
| REFUND_DIFF 退款差异 | 退款单与银联退款文件不一致 | 同上逻辑 |

### 6.4 核销流程（人工）

```
运营查看差异列表 → 逐条核查（本地单据/银联查询/联系银联）
  → 处理方式：
     ① 确认无误 → 核销（记录操作人/原因）
     ② 确认差错 → 发起冲正/补单（走调账，二期自动化；一期人工+记录）
     ③ 需银联介入 → 工单，挂起
差异状态：待核销 → 已核销 / 已挂起
```

### 6.5 关键设计约束

1. **对账是最终兜底**：支付单长期 UNKNOWN 未收敛 → 以对账文件结果为准修正（对账完成前不主动改单，完成后批量修正）。
2. **幂等与重跑**：对账任务按（通道, 日期）幂等；重跑清空该日差异重新比对。
3. **手续费对账预留**：银联文件含手续费字段（30 列"手续费"列）→ 落库与 txn_flow.fee_amount 核对。
4. **样例已确认**：对账模板字段已拿到（04 §12），二期解析器按样例开发，联调用真实文件回归。
5. **告警**：差异数 > 阈值（如 5 笔）或出现 SHORT_PAY → 通知运营（短信/群消息）。

### 6.6 对账报表（操作后台二期）

- 对账总览：日期、通道、我方笔数/金额、银联笔数/金额、差异数
- 差异明细：按类型/状态筛选，导出
- 核销记录：操作留痕
